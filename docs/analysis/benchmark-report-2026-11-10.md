# 性能测试报告 — v0.5.0 发布验证基准

> 日期：2026-11-10。目标：v0.5.0 正式发布后（含 11 月全部引擎改动 + maven-minor 依赖升级
> fastjson2 2.0.66 / Boot BOM 3.5.16）的性能回归验证。
> 结论先行：**四个场景全部通过内建断言门限，余量 34x–217x；与 7 月基线同量级，无回归信号。**

## 1. 环境与版本

| 项 | 本地 | CI 对照（PR #16 run） |
| --- | --- | --- |
| CPU | Apple M5 Pro | ubuntu-latest 共享 runner |
| 内存 | 48 GB | runner 标准 |
| JDK | OpenJDK 21.0.11 | Temurin 17 |
| Maven | 3.9.16 | 3.9.x |
| 代码版本 | `462044c` (main) | #16 分支（与 main 同差集） |

## 2. 方法

`PerformanceBenchmarkTest` 四场景（`-Pbenchmark`），每个场景含独立断言门限：

| # | 场景 | 模板形态 | 迭代 | 预热 | 断言门限 |
| --- | --- | --- | --- | --- | --- |
| 1 | Simple | 字符串模板 2 占位符 `{@name}`/`{@age}` | 冷 10k / 热 100k | 无显式 | warm < 100 μs |
| 2 | JSON | 6 字段嵌套 JSON 模板 | 热 50k | 无显式 | warm < 500 μs |
| 3 | Script | 2 个 Groovy 表达式 `{= … }` | 热 10k | 100 次 | warm < 5 ms |
| 4 | Each | `@class:each` × 100 items（含 Groovy 价格表达式） | 热 1k | 10 次 | warm < 50 ms |

本地各跑 3 次取中位数估方差；CI 为单次。跨环境数字不可直接相减，仅比量级与场景间比值。

## 3. 结果

### 3.1 本地（3 次，ns/call）

| 场景 | Run1 | Run2 | Run3 | 中位数 | 门限余量 |
| --- | --- | --- | --- | --- | --- |
| Simple 冷 | 600 | 1,100 | 700 | **700** | — |
| Simple 热 | 460 | 680 | 510 | **510** | **196x**（<100μs） |
| JSON 热 | 4,360 | 4,340 | 3,220 | **4,340** | **115x**（<500μs） |
| Script 热 | 25,100 | 29,400 | 27,100 | **27,100** | **184x**（<5ms） |
| Each×100 热 | 1,452,000 | 1,124,000 | 774,000 | **1,124,000** | **44x**（<50ms） |

Simple 场景 JIT 加速比（冷/热）：1.3x / 1.6x / 1.4x。

### 3.2 CI runner 对照（单次，ns/call）

| 场景 | CI | 本地中位 | CI/本地 |
| --- | --- | --- | --- |
| Simple 热 | 1,600 | 510 | 3.1x |
| JSON 热 | 11,040 | 4,340 | 2.5x |
| Script 热 | 57,000 | 27,100 | 2.1x |
| Each×100 热 | 2,152,000 | 1,124,000 | 1.9x |

CI 为共享 2-vCPU runner，整体慢 ~2-3x 属正常；**场景间比值完全一致**
（JSON ≈ 7x Simple、Script ≈ 24x Simple、Each ≈ 132-215x Simple，两环境同构）——
比值同构说明无场景特异性回归。

### 3.3 与 0.5.0 开发期基线对照（`docs/release-notes-0.5.0.md`，2026-07）

| 场景 | 7 月基线 | 本次本地中位 | 变化 |
| --- | --- | --- | --- |
| Simple 热 | 360 | 510 | +42% |
| JSON 热 | 3,920 | 4,340 | +11% |
| Each×100 热 | 949 μs | 1,124 μs | +18% |

三点说明：
1. 7 月基线的测量环境未知（非本机 M5 Pro），跨环境 ±20-40% 属噪声区间；
2. 期间引擎新增了 round-1/2 的安全与正确性机制（沙箱缓存、trace 守卫、rest hardening 等），
   热路径换来了正确性/安全性；
3. 简单模板热路径仍在 **sub-μs 量级**（0.36 → 0.51 μs），JSON 单次 ~4.3 μs，与"7 个组件
   + Groovy + schema 校验全开"的引擎定位相称。

## 4. 分析

- **Script 场景 27 μs/call** = 2 个 Groovy 表达式 → 单脚本求值 ~13.5 μs。这是
  JSR-223 eval + bindings 构建的成本，编译已由 ScriptEnvironment 的 Caffeine 缓存
  （v0.5 引入）消除——成本集中在执行段，符合预期。
- **Each×100 = 1.12 ms → 11.2 μs/item**：每 item 一次 Groovy 表达式
  （`$item.price * 1.1` ≈ 13.5 μs）+ 子模板渲染，两项相加与实测吻合，无异常放大。
- **Each 本地方差 0.77–1.45 ms（±30%）**：1k 迭代样本在 JIT/GC 干扰下的正常波动；
  需要更紧的数字时用 JMH（`-Pbenchmark` 的手写循环适合健康检查，不适合基准发布）。
- **CI Simple 冷热比 0.9x**：共享 runner 上 JIT 在 100k 次内基本没热起来，冷≈热；
  不是缺陷。
- 依赖升级（fastjson2 2.0.53 → 2.0.66 等）未见场景特异性退化：比值同构 + 全部门限余量巨大。

## 5. 结论

1. 四场景断言门限全部通过，余量 **44x–196x**——性能预算极充裕。
2. 与 7 月基线同量级（Simple sub-μs / JSON ~4 μs / Each ~1 ms/百条），无回归信号。
3. 引擎成本模型清晰：模板解析已被 LRU 缓存消除（compile API + parseStrTemplate 缓存）、
   Groovy 编译已被脚本缓存消除，剩余成本 = 渲染树遍历 + 表达式求值。
4. 观察池既有项不变：P4 renderString O(k·n) 只影响多占位符长模板（本次场景未覆盖），
   等真实信号再立项。
